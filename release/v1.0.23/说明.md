# Droidspaces v1.0.23-6.12

完整可刷入模块包，不是补丁。含 4 个内核模块 `.ko` + 全套 WebUI / 脚本，KernelSU / Magisk / APatch 直接刷，或解压覆盖 `/data/adb/modules/Droidspaces`。

版本号 `v1.0.23-6.12`（versionCode 10023）。相对上一个发布版 **v1.0.20**：2 个内核模块 + 2 个用户侧文件有变，其余逐字节相同。

## 修了什么

### 关机 / 整机卡死

- userns 权限检查在 RCU 读侧临界区里取 mutex，内核报 `Voluntary context switch within RCU read-side critical section` → 改为 `ns.ops` 指针比较，不睡眠、不加锁
- 厂商 `update_ddl_hit_history` 用 pid 当直方图下标，越界落进 UBSAN 的 `BRK #0x512`，直接 panic → 越界改道返回
- `pid_max` 被容器改大后没压回 → 持续轮询，1 秒内压回 32768

### 容器检测

- img 格式容器显示「容器总数: 0」→ 补 `/mnt/Droidspaces/<name>/etc` 判据
- userns 支持判定恒为真 → 改看 `/proc/sys/user/max_user_namespaces`

### 换源

- 只认展开目录，`rootfs.img` 容器一律失败 → 五级回退定位 rootfs
- 只写 `sources.list`，deb822 系统改了等于没改 → 识别 `*.sources` 就改写它，并停用旧文件
- Debian 容器被按 Ubuntu 地址写 → 补 debian 分支
- IPv6 黑洞导致 `Temporary failure resolving` → ForceIPv4 + `gai.conf` 优先级

## 安装

KernelSU / Magisk 直接刷 zip。或手动：

```bash
cd ~ && rm -rf v123 && unzip -o "/sdcard/Download/Droidspaces-v1.0.23-6.12.zip" -d v123
su -c "cp -a $HOME/v123/. /data/adb/modules/Droidspaces/"
su -c 'chmod 755 /data/adb/modules/Droidspaces/mirror.sh'
```

只换 WebUI、不动 ko：

```bash
su -c "cp $HOME/v123/mirror.sh /data/adb/modules/Droidspaces/mirror.sh"
su -c "cp $HOME/v123/webroot/index.html /data/adb/modules/Droidspaces/webroot/index.html"
```

## 验证

```bash
su -c 'cat /proc/sys/kernel/pid_max'                          # 应为 32768
su -c 'sh /data/adb/modules/Droidspaces/mirror.sh list'       # 应识别出容器与源
```

`list` 正常输出：

```
[1] ai  Debian GNU/Linux 13 (trixie)  (debian/trixie)
    源: https://mirrors.ustc.edu.cn/debian/
    根: /mnt/Droidspaces/ai
---
容器总数: 1
镜像挂载点: /mnt/Droidspaces
```

## 限制

换源 / DNS 只能在**容器运行时**使用。`rootfs.img` 没 loop 挂载时，宿主侧只是一堆二进制，脚本会打印「容器未运行，rootfs.img 没 loop 挂载」。

v1.0.20 的 `droid_lkm_misc.ko`（`15fc08cb`）不含 RCU 修复，不要回退内核。
