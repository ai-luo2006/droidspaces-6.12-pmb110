# Droidspaces v1.0.23-6.12

**这是完整可刷入模块包**，不是补丁。含 4 个内核模块 `.ko` + 全套 WebUI / 脚本，可直接用 KernelSU / Magisk / APatch 刷入，或解压后手动覆盖 `/data/adb/modules/Droidspaces`。

版本号 `v1.0.23-6.12`（versionCode 10023），内核模块二进制与 v1.0.22 完全相同，只更新了 WebUI 两个文件。

## 与 v1.0.22 的差异

只有两个文件变了：

| 文件 | v1.0.22 | v1.0.23 |
|---|---|---|
| `mirror.sh` | 7433 B `4dedaedae8d60dfc75fd98fb7a356211` | 13007 B `dac5ab5398bc0513eb994c036c716854` |
| `webroot/index.html` | 76716 B `75f679574e0347b46eead02789b405a7` | 78030 B `45b3bdfcf894751656f655bb97e889f6` |

内核模块（4 个 `.ko`）逐字节一致，md5 见 `checksums.txt`。**已经在跑 v1.0.22 且不想重启的，只覆盖这两个文件即可，不必重刷模块。**

## WebUI 修了什么

### 1. 容器探测：支持 rootfs.img

原逻辑只认「展开目录」布局（`[ -d "$c/rootfs/etc" ]`），而本机容器是 8 GB 镜像 + loop 挂载：

```
/data/local/Droidspaces/Containers/ai/rootfs.img
/dev/block/loop12 /mnt/Droidspaces/ai ext4 rw
```

于是「容器总数: 0」，换源直接退出。新版 `ctr_root()` 五级回退：

1. `$c/rootfs/etc` —— 展开目录
2. `container.config` 的 `name=` → `/mnt/Droidspaces/<name>` —— **本机走这条**
3. `rootfs_path` 本身是目录
4. 扫 `/proc/mounts` 中 `/mnt/Droidspaces/` 下名字匹配的挂载点
5. 借容器进程 `/proc/<pid>/root`（仅 img 容器，避免撞上无关进程）

同时修了 `do_src` 的位置参数错误（函数内 `$2` 取不到脚本参数，会错误地回退到第一个容器）。

### 2. deb822 源文件

Debian 12+ / Ubuntu 24.04+ 默认读 `sources.list.d/debian.sources`，不再是 `sources.list`。原版只写 `sources.list`，结果是换源等于没换，还会因为双份配置让 apt 报 `Target Packages is configured multiple times`。

新版：检测到 `*.sources` 就改写 deb822（`Types` / `URIs` / `Suites` / `Components` / `Signed-By`），并把旧 `sources.list` 整份注释停用。`src` 动作也会把 `debian.sources` 一起打出来。

### 3. ForceIPv4

容器从路由通告拿到 `default via fe80::1`，于是 glibc 认为 IPv6 可用，apt 优先连 AAAA 记录；但那个网关并不真转发 IPv6，最后报成 `Temporary failure resolving`。

DNS 动作现在写：

```
Acquire::Retries "3";
Acquire::http::Timeout "15";
Acquire::ForceIPv4 "true";
```

并在 `gai.conf` 里设 `precedence ::ffff:0:0/96 100`，让 curl / pip / docker 一起避开。

### 4. 检测页

- `probeCtr()` 增加 `/mnt/Droidspaces/<name>/etc` 判据，与 `mirror.sh` 统一
- `U=$([ -e /proc/self/uid_map ])` 这个判断恒为真，改为读 `/proc/sys/user/max_user_namespaces`
- `showSrc()` 改为调用 `mirror.sh src`，不再在 JS 里拼 `Containers/<name>/rootfs/etc/apt`
- `doDiag()` 诊断包加入 `/proc/mounts` 与 `container.config`
- `container.config` 的值带 `\r`（CRLF），读取时统一 `tr -d '\r'`

### 5. 提示文案

`do_list` 逐个说明「为什么跳过」（目录异常 / img 未挂载 / 未初始化），不再只说一句「没找到容器」；Debian 容器不会再被标成 `ubuntu-ports`。

## 安装

KernelSU / Magisk 直接刷 zip。或手动：

```bash
cd ~ && rm -rf v123 && unzip -o "/sdcard/Download/Droidspaces-v1.0.23-6.12.zip" -d v123
su -c "cp -a $HOME/v123/. /data/adb/modules/Droidspaces/"
su -c 'chmod 755 /data/adb/modules/Droidspaces/mirror.sh'
```

只换 WebUI、不动 ko：

```bash
su -c "cp $HOME/v123/mirror.sh /data/adb/modules/Droidspaces/mirror.sh"
su -c "cp $HOME/v123/webroot/index.html /data/adb/modules/Droidspaces/webroot/index.html"
```

## 验证

```bash
su -c 'md5sum /data/adb/modules/Droidspaces/mirror.sh /data/adb/modules/Droidspaces/webroot/index.html'
su -c 'sh /data/adb/modules/Droidspaces/mirror.sh list'
```

```
    根: /mnt/Droidspaces/ai

```

## 限制

换源 / DNS 只能在**容器运行时**使用。`rootfs.img` 没被 loop 挂载时，宿主侧只是一堆二进制，脚本会明确打印「容器未运行，rootfs.img 没 loop 挂载」。本机 `run_at_boot=1`，正常开机就在跑。

## 崩溃修复没变

内核部分与 v1.0.22 完全一致：

- `pid_max` 1 秒轮询压回 32768（`dlc_pid_max_work_fn`）
- 厂商 `update_ddl_hit_history` 越界改道返回（`ddl guard`）
- userns 在 RCU 读侧临界区不再拿 mutex

三者叠加，`task->pid` 永远到不了厂商 32768 项数组之外。
